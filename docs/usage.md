# Usage & Review

本文说明 `dsh-prompt-refine` 的日常使用方式，包括 Composer 优化、局部优化、`/refine` 命令、重新生成、撤销和 Diff Review。

## Composer Refinement

1. 在 DSH Composer 中输入 Prompt。
2. 如果只希望优化部分内容，先选中对应文本。
3. 点击 **优化提示词**。
4. 等待模型完成生成。
5. 检查写回结果。
6. 根据需要重新生成、撤销或点击 **完成**。

插件不会自动发送消息，最终是否发送仍由用户决定。

## Selection Refinement

存在文本选区时，插件只处理被选中的纯文本。

如果选区跨越 DSH 的引用结构，插件会拒绝本次优化，以避免破坏引用占位信息。

## `/refine` Command

```text
/refine 帮我检查这轮代码有没有问题
```

插件只优化 `/refine` 后面的正文，命令前缀不会作为提示词内容发送给模型。

## Review and Regeneration

生成完成后可进行：

- **原文**：查看优化前 Prompt；
- **补充要求**：添加只对下一次生成生效的额外要求；
- **重新生成**：基于原始 Prompt 和当前补充要求重新生成；
- **停止生成**：终止当前尚未完成的请求；
- **撤销优化**：在草稿仍满足安全条件时恢复原始 Prompt；
- **完成**：结束本轮优化并清理 review 状态。

重新生成始终基于原始 Prompt，而不是上一轮生成结果：

```text
Original
├── Generate A
├── Regenerate + Note → B
└── Regenerate + Note → C
```

## Diff Review

插件会对优化后的结果进行行内差异标记：

- **绿色**：新增或扩写内容；
- **红色虚线**：局部替换内容；
- **纯删除**：没有可着色的结果文字，不显示删除标记，也不将被删除的原文插入 Composer。

差异标记始终比较固定原文与当前草稿，只展示结果文字上的变化，不改变正文。固定原文用于「原文」、重新生成和撤销。

## Manual Editing

优化结果写回后仍可继续手动编辑。

全文优化时，操作条会持续同步当前草稿，并在输入停顿约 200ms 后重新计算「原文 ↔ 当前草稿」的差异，无需关闭面板。中文输入法组合期间暂停刷新，组合结束后恢复。若仅有 DOM 节点重建，也会重新映射高亮，不修改正文或光标。

手动内容与最近一次成功回填的结果不同，撤销或重新生成前会在操作条内显示覆盖确认。点击「确认覆盖」继续，点击「取消」保留草稿；确认后仍会校验草稿版本，避免覆盖确认之后的新输入。重新生成只向模型发送固定原文和补充要求，不发送手动修改后的草稿。

生成期间编辑会取消本次请求，但全文编辑会话仍然可用。生成失败或停止时保留上次成功结果和 Diff。

选区优化（包括 `/refine` 正文）采用保守范围校验：草稿文字、版本或相关元数据变化后，会保守停止高亮、撤销和重新生成，提示范围无法可靠定位；不会猜测位置或覆盖选区外内容。全文草稿新增引用时也采用此保护。发送或点击「完成」后结束会话并释放观察器和订阅。
