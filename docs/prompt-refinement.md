# Prompt Refinement

`dsh-prompt-refine` 根据 Prompt Engineering 原则改善用户准备发送给 AI Agent 的提示词。

## Optimization Dimensions

### Intent

明确用户希望 Agent 完成的核心目标。

### Context

明确完成任务时应该利用的已有信息，例如当前代码、已有实现、本轮修改、文件材料或前文上下文。

### Requirements

补充与原始目标直接相关的重要要求和关注点。

### Method

当执行方式会明显影响结果质量时，可以补充分析思路、执行顺序和检查方法。

### Constraints

完整保留并明确用户已经给出的范围、兼容性、技术和修改边界。

### Output

在必要时明确最终应该交付的结果。

### Verification

对于开发、测试、评审、分析等任务，可以补充与原始目标直接相关的验证方式。

## Adaptive Optimization

### Clarify

适用于已经比较明确的简单 Prompt。

```text
解释一下这个函数
```

优化为：

```text
解释这个函数的主要作用、输入输出和执行逻辑，并说明其中关键代码分别负责什么。
```

### Enhance

适用于目标明确但缺少部分执行信息的 Prompt。

例如：

```text
给这次修改写点测试，看看有没有问题
```

会补充实际变更范围、测试关注点和验证结果要求。

### Structure

适用于复杂、多步骤、多约束 Prompt。

此时可以通过自然分段、列表或结构化内容帮助 Agent 理解任务，但不会机械套用固定模板。

## Information Grounding

优化器优先使用 Prompt 中已经明确的信息。

对于未知的项目事实，不自行指定未经确认的框架、文件、接口、工具或技术方案，而使用：

- “结合当前实现”
- “根据实际代码变更”
- “沿用项目现有方式”
- “参考已有结构和规范”

等上下文适应性表达。

## Language

优化后的 Prompt 默认保持原始 Prompt 的主要语言。

## Example

### Before

```text
看看为什么这里一直报错
```

### After

```text
结合当前报错信息、相关代码和实际调用路径分析错误原因。先定位错误发生的位置和触发条件，再检查相关输入、状态变化、依赖调用以及异常处理是否符合预期。区分代码逻辑问题、配置或环境问题以及上下游依赖问题，并根据实际证据给出原因判断和对应的修复建议。
```
